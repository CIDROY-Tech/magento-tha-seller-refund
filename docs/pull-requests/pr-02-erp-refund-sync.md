# Add ERP tax mapping and refund retry handling

Wires the refund submit to the ERP Create Refund call so the operator gets `erp_refund_id` in the save response, maps the `mp_tax_class` attribute into the payload's `taxes` array grouped per SKU with the tax mode passed explicitly, and gives each attempt its own request key so ERP-side audit entries can be told apart. Failed calls mark the refund for retry from the operator worklist grid, which gains seller, SKU and order-total columns. Includes a small refactor of the connector and payload builder and records the request key on refund events. Testing: happy path against the local stub (submit -> refund-pending -> cash registration -> confirm) on a delivered seller order; unit tests updated for the new payload shape and dispatch flow.
